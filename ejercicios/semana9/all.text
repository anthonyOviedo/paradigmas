INICIO RESUMEN CLAUSURAS
Hago un resumen acá sobre clausuras: La idea es que toda lambda se representa como un objeto que tiene la memoria (state) de los parámetros y variable locales de la lambda.
A ese objeto se le llama una clausura. Además este objeto apunta a la memoria (state) de la clausura en la que se creó la lambda.
	Ejemplo:
	Asuma un archivo test.js que define como tal un state con la compilación y evaluación  de la siguientes declaraciones en el mismo:
const a = 1
let b = "hola"
const foo = x => x + a
console.log(foo(b))

Habría un state de test.js (digamos test_state) en el que viven esos identificadores. Figurativamente lo podemos visualizar como si fuera una especie de  diccionario:
	  test_state = {a:1, b: "hola", foo: clausura({x:null, parent_state: test_state}, lambda: x => fx + a }
	 
 Al evaluar por ejemplo foo(b) en test.js (aplicativamente, piense en el AST de foo(b)) se hace lo siguiente:
	  a) Se evalúa foo que significa buscarlo en el test_state donde tiene como valor la clausura
	  clausura({x:null, parent_state: test_state}, lambda: x => x + a }  notando que x no tiene un valor real, digamos tiene null.
	  b) Se evalúa b, igualmente se busca en el state test_state y se encuentra como la hilera "hola"
	  c) Se hace la aplicación o beta reducción foo(b), para eso:
	     c1) Se actualiza primero el state a {x:"hola", parent_state: test_state}
	     c2) Se evalua x + a en el state de la clausura actualizado. Es decir,
		     c2.1) Se evalúa x en el state de la clausura que resulta en acceder a "hola"
		     c2.2  Se evalúa a en el state de la clausura, pero como no está ahí se busca en el state padre parent_state , en el que a vale 1, ese es el valor de a.
			 Se hace la suma "hola" + 1 que resulta en "hola1" (+ es concatenación acá)
	     c3) Se retorna "hola1" como resultado final de foo(b).
	
Note como usar clausuras evita hacer la sustitución del la variable x con "hola" físicamente, lo cual sería muy ineficiente.  
También hace innecesarias las alpha-conversiones.
	
Note que como  a no es parámetro de foo sino que está definido en el state de test.js (top level) que es el padre del state de la clausura asociada a foo. 
Cuando un identificador no está en el state de una clausura se busca recursivamente el parent state 
(que puede ser el de otra clausura. Si al final de  esa cadena no se encuentra se reporta un error (de semántica dinámica) que en JS es como 
Uncaught ReferenceError: x is not defined si x es el identificador siendo buscado.

Definición:
Dos expresiones E1 y E2 se dicen Leibniz-equivalentes si para todo programa P que use E1 si cambiamos E1 por E2 en P y ejecutamos P 
los resultados de P antes y después del cambio en idénticas situaciones son los mismos. Es decir, P es invariante a cambios de E1 por E2 para cualquier P.
